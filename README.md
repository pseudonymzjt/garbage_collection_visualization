# GC Sandbox | 垃圾回收算法可视化实验场

这是一个专为计算机导论/系统级课程设计的**交互式垃圾回收（Garbage Collection）演练沙盒**。

本项目基于极简的 Web 技术栈构建，将底层抽象的内存管理机制（标记-清除算法、引用计数算法）具象化为直观的节点图，并采用“慢动作”时间调度算法，完整展现了内存扫描、级联回收以及垃圾清理的动态过程。

---

## 🌟 项目亮点

1. **确定性的异步调度算法**：摒弃了瞬间完成的同步递归，利用 JavaScript 异步函数（`async/await`）与 Promise 延迟机制，实现了可暂停、可调速、步骤清晰的“慢动作”可达性扫描动画。
2. **零第三方图形库依赖**：项目未引入任何重度 Canvas 或物理引擎库，完全基于 **普通 DOM 节点 + SVG 原生画布** 绘制带有箭头指向的引用关系线，技术实现简洁且高容错。
3. **兼容双版本**：项目同时提供 **React 版**（Vite 构建）和 **纯原生 JavaScript 版**（零外部依赖），后者解压即用，无需 Node.js，双击 `index.html` 即可运行。
4. **直观的学术对比演示**：内置一键加载“循环引用（Circular Reference）”场景，通过在沙盒中分别运行“引用计数”和“标记-清除”两种算法，直观对比并印证两者的学术优缺点与理论瓶颈。
5. **友好的交互设计**：
   * **鼠标拖拽**：可自由排版和拖动内存块。
   * **点击连线**：依次点击两个节点即可快速建立单向指针。
   * **右键删除**：右键点击任意节点即可快速销毁对象并自动清理游离指针。

## 📖 交互与演示指南（答辩推荐流程）

为了在答辩或演示时获得更好的展示效果，建议按照以下步骤向评委老师演示：

### 步骤一：手动构建内存图
1. 点击左侧控制台的 **“+ 新增内存对象”** 按钮数次，在画布中生成若干灰色内存块。
2. 鼠标按住并拖动这些圆圈，将它们随意排版。
3. 点击 **“🔗 点击节点建立连线”** 进入连线模式，先点击绿色根节点 `Root`，再点击 `Obj_0`。
4. 依次连接其他节点，手动构建出一棵“引用树”。观察非 Root 节点右上角的引用计数（`rc` 角标）是如何实时根据指针变化而增减的。

### 步骤二：对比演示（核心硬核展示）
1. 点击左侧按钮 **“🌀 加载：循环引用缺陷场景”**。此时画布上会自动生成：
   * 正常可达链：`Root ──> Obj_A`。
   * 无法从根节点触达的循环引用：`Obj_B <──> Obj_C`（两者相互指向，但与 Root 断开）。
2. **演示一：引用计数算法的缺陷**
   * 观察发现，`Obj_B` 和 `Obj_C` 的红色角标显示其引用计数（`rc`）依然为 `1`。
   * 点击左侧的 **“运行：引用计数 (Reference Counting)”**。
   * **观察结果**：算法运行后，由于 `B` 和 `C` 的计数不为 0，它们依然残留在画布上，无法被回收。由此向评委证明：*引用计数算法无法解决循环引用导致的内存泄露问题*。
3. **演示三：标记-清除算法的优势**
   * 点击左侧的 **“运行：标记-清除 (Mark-Sweep)”**。
   * **观察结果**：
     * **标记阶段**：黄色光芒从 `Root` 出发，顺着指针单向传导至 `Obj_A`。由于 `B` 和 `C` 无法从根节点触达，它们没有变黄。
          * **清扫阶段**：未被标记的 `Obj_B` 和 `Obj_C` 开始向中心缩小并淡出，最终被完全清除。由此向评委证明：*现代垃圾回收器采用的可达性分析（Mark-Sweep）能有效解决循环引用对象的回收*。

### 步骤三：Java 关卡挑战（6 大经典内存泄漏场景）
1. 在左侧 **关卡选择** 下拉菜单中，选择 L1 ~ L6 中的任一关卡。
2. 根据右侧 **Java 代码对照区** 的提示，分析泄漏原因。
3. 在画布中通过 **连线模式 / 删除连线模式** 编辑引用关系。
4. 运行对应 GC 算法，观察内存是否被成功回收。
5. 通关后，右侧代码区会自动高亮修复后的代码，并显示通关徽章。

## 🎮 六大 Java 内存泄漏关卡

| 关卡 | 名称 | JVM 泄漏场景 | 解谜方式 |
|:---|:---|:---|:---|
| L1 | 静态集合膨胀 | `static List` 持有临时数据引用 | 断开 `staticCache -> tempData` 的连线 |
| L2 | 循环引用的孤岛 | 孤立对象 `b <-> c` 互相引用 | 剪断环路使引用计数归零 |
| L3 | 堆内存强引用解耦 | 多余强引用指向大 `byte[]` 缓冲区 | 删除冗余边使内存 <= 10MB |
| L4 | 监听器未注销 | 全局 EventPublisher 持有监听器 | 斩断 `EventPublisher -> Listener` |
| L5 | ThreadLocal 遗留 | 线程复用但未调用 `remove()` | 切断 `ThreadLocalMap -> UserContext` |
| L6 | 未取消的后台 Timer | Timer 线程未调用 `cancel()` | 清除 Timer 与 JVM_Roots 的连接 |

## 📝 核心算法逻辑说明

* **Mark-and-Sweep**：从 `isRoot` 为 `true` 的节点出发，利用基于队列的广度优先搜索（BFS）进行可达性扫描。扫描过程中通过更新节点状态，利用 CSS 的 `transition` 属性在前端实现柔和的黄色高亮和淡出删除动画。
* **Reference Counting**：实时监听 `edges` 状态。执行垃圾回收时，扫描并挑出非 Root 且引用计数为 0 的节点。删除这些节点后，会同步断开它们引出的边，可能导致相邻节点引用计数降至 0。算法采用 `while` 循环和级联变量更新，优雅实现了级联删除（Cascade Delete）效果。
